  (`module_federation_enabled: true`, `sales_rep_builtin_enabled: false`, VirtoCommerce/vc-frontend#2569).

  22rem so its full-size calendar fits (VirtoCommerce/vc-frontend#2536); the theme's rail is the design's.
  Take upstream's other changes to these files (Tasks route, row markup). Obvious.
- **`header-plate.vue` renders the `topHeaderStatus` extension point**, inside `header-plate__status`,
  which gives module labels the preferences pill's size and ink and hides empty divider spans. Upstream's
  labels are drawn for its dark top bar (14px bold, a red rule as an empty span). User.
- **The punch-out label is desktop only, as upstream.** Below `lg` both headers switch to the mobile
  header, which has no status slot. Upstream gap, not the fork's: if the punch-out module ever registers
  a mobile entry, it reaches the fork through `mobileHeader`. User (option 1).
- **`compare-table.vue` takes upstream's structure** (one native `<table>`, VirtoCommerce/vc-frontend#2518)
  **with the fork's deltas on top**: `VcTabSwitchGroup` (seg, fill, aria-label, test ids), `--edge-radius`
  from `--vc-widget-radius`, the pinned row's wedge-backing shadow, `max-w-fit` tabs below md. Obvious.
- **The root `package.json` keeps the fork's own version** (3.1.0), unchanged from the last log.
